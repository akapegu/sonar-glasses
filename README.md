# SoniSpeech baseline: implementation spec

This is a spec for Claude Code. It describes how to reproduce the SoniSpeech
baseline (ResNet-34 + CTC) on the public dataset, starting with data
exploration on a single zip.

Source paper: SoniSpeech, arXiv 2608.00803. The settings below come from the
paper and the dataset README. Anything the paper does not state is marked
**UNKNOWN**, with a default value to start from.

---

## 0. Goal and success criteria

Train a silent-speech recognizer that reads ultrasound echo profiles and
outputs text, and match the paper's numbers within about 1–2 WER points.

| Trained on | Voiced test WER | Silent test WER |
| --- | --- | --- |
| Voiced only | 16.9% | 78.4% |
| Silent only | 55.7% | 33.7% |
| Voiced + silent (main target) | 15.8% | 26.3% |

Rules:

- **Never tune on the test set.** Tune on validation only.
- Always report voiced and silent WER separately.
- Change one thing at a time. Log every run with its config.

## 1. Dataset facts (from the dataset README)

- 9 zips, 76.94 GB in total. Licence CC BY-NC 4.0 (research use only).
- Layout: `SoniSpeech_{voiced,silent}_{train,eval}/session_XXX/`
  - `audio.wav`: 100 kHz, 2 channels (one per mic), int16. Audio between
    utterances is zero-masked. The first utterance starts at 2.0 s.
  - `video.mp4`: 30 fps, 1080p. **Not needed for the baseline. Skip extracting it.**
  - `transcript.json`: `{id: {"start": s, "end": s, "transcript": str}}`, with times in seconds.
- Zip 01 contains the official preprocessing code in `echo_profiles/`:
  `echo_profiles.py`, `filters.py`, `plot_profiles.py`, and
  `tx_signals/fmcw18000_b10000_l500_100k.wav` and `fmcw29000_b10000_l500_100k.wav`.
- Running `python echo_profiles/echo_profiles.py` from the dataset root writes
  `echo_profiles.npy` and `diff_echo_profiles.npy`, each of shape
  `(2 speakers, 2 mics, n_frames, 500)`, plus PNG plots. Dependencies: numpy,
  scipy, opencv-python.
  - **Caution (checked against the code):** as shipped, `main()` only processes
    `SoniSpeech_silent_eval`; the other three splits are commented out. It also
    saves **float64, full 500 bins**, inside the dataset folders: about 1 GB per
    `.npy` for a 5-minute session, two files per session. **Do not run `main()`
    over the dataset.** Import `calculate_echo_profiles` and crop/cast at once.
  - The code does **no normalisation** beyond scaling int16 by 1/32768. The
    differential profile is `|p_t| - |p_(t-1)|` along time, with a zero frame
    padded at the start.
  - The audio is trimmed by `start_pos` (0-499 samples) so that the strongest
    correlation peak (the direct path) lands at **bin 250**, the middle of the
    frame, not near bin 0. Frame `f` therefore starts at sample
    `start_pos + 500 f`.
- 31 sessions have mic channel 1 replaced by a copy of channel 0:
  voiced_train sessions 150–160 and silent_train sessions 141–160.
- **EDA finding (all 9 zips): the official list is incomplete.** Mic 1 also
  has rail-to-rail int16 jumps (the same corruption) in sessions not on the
  list, and one utterance has a loud transient on both mics. Every listed
  faulty session has mic 1 = mic 0 exactly, and no other session does.
  Utterances to drop, 34 in total, are in `eda/drop_list.csv` (generated by
  `scripts/corpus_check.py`):

  | Session | Utterances | Reason |
  | --- | --- | --- |
  | voiced_train 135 | 18 (`train_06700`–`06717`) | corrupt mic 1, 1.7 M jumps |
  | silent_train 126 | 8 | corrupt mic 1 |
  | voiced_train 149 | 3 | corrupt mic 1 |
  | voiced_train 004, 010 | 1 each | corrupt mic 1 (2 jumps) |
  | silent_train 001 | 1 (`train_00038`) | transient on both mics |
  | voiced + silent_train 029 | 1 each (`train_01446`) | sentence also in test |

  Voiced 135 and 149 and silent 126 all sit just below the official faulty
  ranges (voiced 150+, silent 141+), consistent with mic 1 failing gradually.

Signal facts:

- Two FMCW chirps. Speaker 0 sweeps 18–28 kHz, speaker 1 sweeps 29–39 kHz.
  Each chirp is 500 samples (5 ms) at 100 kHz.
- That gives 200 frames per second and 4 sound paths (2 speakers × 2 mics).
- One sample is about 3.4 mm of path length, so 80 bins cover about 27 cm.

## 2. Phase A: exploratory data analysis (one zip)

Do this first, in `notebooks/01_eda.ipynb` or `scripts/eda.py`. Write findings
to `eda/` (HTML reports plus `eda_findings_<zip>.md`).

1. **Inventory.** List the splits and sessions present in the zip, and the disk
   size of each file type.
2. **Audio checks.** Confirm the sample rate (100 kHz), channel count (2) and
   dtype (int16). Plot a spectrogram of 1 s of audio: there should be two
   bright bands, at 18–28 kHz and 29–39 kHz. In voiced sessions, speech energy
   should also appear below 8 kHz.
3. **Transcript checks.** Count utterances per session (expected 50). Plot the
   distribution of utterance durations (paper: about 5.26 s voiced, 5.41 s
   silent) and words per utterance (about 14.4 ± 5.3). Confirm the gaps between
   utterances are zeroed in the audio.
4. **Run the official script** on one session. Record the output shapes, dtype,
   runtime and memory use.
5. **Read `echo_profiles.py` and `filters.py`** and document exactly what they do:
   filter design, how frames align to chirps, the correlation method,
   normalisation, and how the differential profile is computed. This settles
   several of the UNKNOWNs in section 10.
6. **Plot one utterance's differential profile.** Show 4 panels (one per path),
   range bins ~200–350 on the y-axis (the direct path sits at bin 250, see
   section 1) and time on the x-axis. Mark the utterance start and end. Check
   which ~80 bins around and after bin 250 carry the motion, and that the
   profile is quiet between utterances.
7. **Faulty-mic check.** For a session in the faulty list, confirm that
   channel 1 equals channel 0.
8. **Memory estimate.** A full session is roughly
   `n_frames × 500 × 4` float32 values. Estimate the per-session size for full
   versus cropped (80 bins, float16) storage.

## 3. Phase B: preprocessing to a training cache

Script: `scripts/preprocess.py`. Process one session at a time, then free memory.

1. Compute differential echo profiles using the official code, imported or
   lightly wrapped. **Do not reimplement it unless necessary**: matching the
   official preprocessing exactly matters.
2. Reshape `(2, 2, T, 500)` to `(4, T, 500)` in the channel order
   `[s0m0, s0m1, s1m0, s1m1]`.
3. Crop the range axis to 80 bins. **UNKNOWN which 80.** The official code puts
   the direct path at bin 250, so `0:80` is wrong. **Frozen: `226:306`**
   (best 80-bin motion-energy window on 18 clean train sessions, 2 per zip,
   9 voiced + 9 silent: window starts 223–232, median 225; keeps ~75% of
   motion energy). Revisit only if a later zip shifts it by more than 3 bins.
4. Cut one sample per utterance:
   `start_frame = floor((start_s × 100000 − start_pos) / 500)`,
   `end_frame = ceil((end_s × 100000 − start_pos) / 500)`
   (`≈ start_s × 200`; the `start_pos` offset is at most one frame).
   Keep the full span.
5. Save each utterance as float16, shape `(4, 80, T)`, with metadata
   (session, mode, utterance id, text, number of frames). Suggested format: one
   `.npy` per utterance plus a `manifest.csv`; use a sharded format later if
   needed.
6. **Normalisation (UNKNOWN in the paper).** Default: per-channel
   standardisation, using the mean and std per channel computed on the training
   set only. Store the statistics in `stats.json` and apply them at load time,
   not in the cache.

## 4. Phase C: splits

**Decided (2026-11-19).** Two stages: develop on a held-out split, then
retrain on exactly the paper's training set for the reported numbers.

| Stage | Train | Validation | Test |
| --- | --- | --- | --- |
| **Dev** (all tuning) | voiced 1–131, silent 1–131 | voiced 132–140, silent 132–140 | not touched |
| **Final** (reported) | voiced 1–140, silent 1–140 (= paper §4.2) | none; settings fixed from dev | all `*_eval` (20 sessions per mode, 1,000 sentences each) |
| Never used | voiced 141–160, silent 141–160 | | |

Why:

- **The session number decides the sentences.** Voiced session N and silent
  session N hold the same 50 sentences (paper §3.3, "parallel" modes; EDA: 14
  pairs, 50/50 shared), and no sentence appears under two session numbers. So
  validation must take the *same* session numbers from both modes, or its
  sentences leak into training through the other mode.
- **132–140 match test conditions:** off the faulty list, two working mics, and
  sentences unseen in training (as in test: 0 of 600 eval sentences appear in
  train so far).
- **141–149 are not used:** the paper trains on 1–140 only; silent 141–160 and
  voiced 150–160 have the duplicated mic channel, so a 141–149 validation set
  would have one working mic in silent mode, unlike test.
- Dev trains on 9 fewer sessions per mode (−6%) than the paper, so dev WER will
  run slightly higher than the paper. The final runs remove that gap.

Rules:

- **Utterance screen:** drop any utterance where a mic has a sample-to-sample
  jump > 30000 (rail-to-rail corruption). Final list: `eda/drop_list.csv`
  (34 utterances, table in section 1; 18 of them are voiced 135, a dev
  validation session, which keeps 32 utterances). The paper almost certainly
  trained on these; record the deviation in every run log.
- Flag faulty-list sessions and screened utterances in the manifest; never
  delete them from the cache.
- **Test-sentence overlap:** a few short sentences occur in both SODA pools
  under different IDs. Drop the *train/validation* copies, never the test copy,
  and log them. Full corpus: exactly one, "Thanks, Frances. That means a lot
  coming from you." (`train_01446` in voiced and silent train 029; test copy
  `test_00490` in eval 010). It is in `eda/drop_list.csv`. After dropping, assert in code: no test
  sentence in train or validation, and no validation sentence in train.
- The final runs take the epoch count (or the best epoch) from the dev runs.

## 5. Phase D: text and tokenizer

- The transcripts are already normalised (numbers spelled out, names mapped).
- One typo to fix before normalising: silent_train 078 `train_03881` has
  "thatDad" (missing space). Voiced/silent transcripts of the same ID differ in
  5 places (e.g. "coat" vs "cast"): these were corrected per mode to what was
  said (paper §3.3), so keep each mode's own transcript. Full list in
  `eda/eda_findings_full.md`. Result: 8,004 unique train sentences, 1,000 test.
- For CTC targets: lowercase and strip punctuation, keeping apostrophes inside
  words (for example "don't").
- Train a SentencePiece **Unigram** model with **1,000 units** on the training
  transcripts only. Index 0 is reserved for the CTC blank, so the model has
  1,001 output classes.
- Save the tokenizer with the run, so fine-tuning later uses the same one.

## 6. Phase E: dataset, augmentation and batching

- **Concatenation augmentation:** with some probability (**UNKNOWN**; default
  0.5), join up to 3 random training utterances into one sample, capped at
  15 s (3,000 frames). Join their transcripts with a space.
- **SpecAugment:** on each training sample, apply 2 masks along the range axis
  and 3 masks along time. Mask widths are **UNKNOWN**; defaults are up to 8
  range bins and up to 40 frames (0.2 s). Fill masked areas with 0 after
  normalisation.
- Do not augment validation or test data.
- **Batching:** batch size 16. Pad along time and keep the true lengths.
  Sorting or bucketing by length is optional and saves compute.

---

## 7. Phase F: model

ResNet-34 adapted for sequences. Input shape is `(B, 4, 80, T)`, treated as an
image with 4 channels, frequency (range) on one axis and time on the other.

- Stem: the conv takes 4 input channels. **Remove the stem max-pool.**
- Temporal downsampling of 16× in total: stride 2 in time in the stem conv and
  in the first block of stages 2, 3 and 4 (2 × 2 × 2 × 2 = 16).
- Range-axis stride is **UNKNOWN**. Default: stride the range axis together
  with time (a standard 2D stride). It is averaged away at the end either way.
- Replace every BatchNorm with **GroupNorm(32 groups)**.
- After stage 4: global average over the range axis, giving `(B, 512, T/16)`.
- A linear layer maps 512 to 1,001 classes, then `log_softmax`.
- Output length: `T_out = ceil(T / 16)`. Compute this exactly from the conv
  arithmetic and pass it to the CTC loss.
- Sanity check: CTC needs `T_out ≥ target_length`. At 12.5 steps per second
  this holds comfortably, but assert it in the data loader.

## 8. Phase G: training

| Setting | Value |
| --- | --- |
| Loss | CTC (blank = 0, `zero_infinity=True`) |
| Optimiser | Adam, learning rate 2e-4, weight decay 1e-4 |
| Schedule | Linear warm-up, then exponential decay. **UNKNOWN details**: default warm-up over the first 5% of steps, decaying to 1% of the peak learning rate by the end |
| Epochs | 200 |
| Batch size | 16 |
| Data | Voiced and silent mixed (main run) |

- Device: CUDA if available, else MPS (Apple Silicon), else CPU. On MPS, the
  CTC loss may be unsupported. If so, compute the loss on CPU or set
  `PYTORCH_ENABLE_MPS_FALLBACK=1`.
- Use mixed precision on CUDA. Clip gradients (default norm 5.0).
- Run validation every N epochs and report greedy WER for voiced and silent
  separately. In dev runs, keep the best checkpoint by **mean validation WER**
  and record its epoch. Final runs (section 4) have no validation set: train
  for that epoch count, or the full 200 if the dev curve has not peaked, and
  evaluate the last checkpoint.
- Seed everything. Save the config, git hash, tokenizer and normalisation
  stats with each run.
- Logging: TensorBoard or a CSV with loss, learning rate and validation WER.

**Smoke test before the full run:** train on 10 sessions for 5 epochs and
check that the loss falls and some decoded words become correct. Then
overfit 20 utterances to near-zero loss, to prove the pipeline can learn.

---

## 9. Phase H: decoding and evaluation

- **Greedy CTC decoding:** take the argmax at each step, merge repeats, remove
  blanks, detokenise with SentencePiece.
- **WER:** use `jiwer`. Normalise the reference and the hypothesis the same
  way (lowercase, no punctuation).
- Report voiced test WER and silent test WER, plus validation numbers.
- Script: `scripts/evaluate.py --ckpt ... --split test` writes per-utterance
  hypotheses to a CSV, for error analysis.

Experiments to run:

1. Voiced + silent (main).
2. Voiced only.
3. Silent only.

## 10. Unknowns and defaults

| Item | Default | How to settle it |
| --- | --- | --- |
| Which 80 range bins | **226:306**, frozen (8 sessions, zips 01–04) (**not** 0:80: the code centres the direct path at bin 250) | Re-check on more sessions; try 240:320 if WER is off |
| Profile normalisation | Per-channel standardisation from train stats | Official code does none (only int16/32768), so this is our choice; check on validation |
| Range-axis stride | Same as time stride | Try both if WER is far off |
| Warm-up and decay | 5% warm-up, decay to 1% | Validation curve |
| SpecAugment widths | Up to 8 bins, up to 40 frames | Validation |
| Concatenation probability | 0.5 | Validation |
| Validation split | **Decided:** dev = train 1–131 / val 132–140, both modes; final = train 1–140 (paper) | Settled (section 4) |

If the final result is more than about 3 points off the paper, check these in
order: input crop and normalisation, the downsampling layout, the tokenizer,
and the augmentation.

```
sonispeech_datasets/

    SoniSpeech_01_of_09/  # also holds the official echo_profiles/ code
    SoniSpeech_02_of_09/ … SoniSpeech_09_of_09/
  papers/                 # paper PDFs and notes
  eda/                    # EDA reports per zip (HTML, metrics, findings)
  explainer/              # concept explainer: data + preprocessing (HTML, figures in img/)
  scripts/                # eda.py, corpus_check.py, make_explainer_figs.py, then preprocess.py, train_tokenizer.py, train.py, evaluate.py
  src/                    # data.py, model.py, decode.py, utils.py (Phase B onward)
  configs/                # baseline_vs.yaml, baseline_v.yaml, baseline_s.yaml
  runs/                   # checkpoints and logs (gitignored)
  cache/                  # preprocessing cache (gitignored, rebuildable)
  .venv/                  # Python environment
```

Keep data paths in the config, never hard-coded. All 9 zips were extracted
without videos (except zip 01, which still has its 40 `video.mp4` files) and
then deleted (2026-11-20) after a byte-level check against the archives. To
re-download one: `unzip <zip> -x '*/video.mp4' -d data/SoniSpeech_0N_of_09`.

## 12. After the baseline (not now)

Ranked next steps, all detailed in the SoniGAN notes doc:

1. A larger language model and lexicon decoding, plus LLM rescoring, ideally
   from an ensemble of diverse models' top-1 guesses (the MONA LISA approach).
2. The SoniGAN recognizer: ResNet-18 plus a 6-layer Transformer, with the
   crossCon loss.
3. Aligning echo profiles to Whisper encoder features and reusing Whisper's
   decoder.
4. Conformer encoder and self-supervised pretraining.
5. Fine-tuning on recordings from our own rig, using the same preprocessing.
